ÉTAPE 4 — AUTOMATISATION ET SUPERVISION (GUIDE POUR LE COLLÈGUE)
=================================================================

Le but c'est de rendre le backup autonome (il se lance tout seul la
nuit) et observable (on voit dans Grafana si ça a marché ou pas).

Le script backup.sh existe déjà et fonctionne. Il faut maintenant :
  1. Le transformer en script orchestrateur complet (rapport JSON)
  2. Créer un timer systemd pour le lancer chaque nuit
  3. Exposer des métriques Prometheus
  4. Créer un dashboard Grafana "Sauvegardes"
  5. Configurer des alertes Alertmanager


CE QU'IL FAUT FAIRE (résumé)
-----------------------------

  1. Enrichir backup.sh pour générer un rapport JSON à la fin
  2. Créer deux fichiers systemd (un .service + un .timer)
  3. Installer node_exporter et utiliser le textfile collector
     pour exposer les métriques de sauvegarde
  4. Ajouter un dashboard Grafana
  5. Ajouter Alertmanager avec deux règles d'alerte


ÉTAPE PAR ÉTAPE
---------------


1) ENRICHIR LE SCRIPT ORCHESTRATEUR (backup.sh)

   Le sujet demande que le script fasse dans l'ordre :
     a) dump des bases de données          → déjà fait
     b) arrêt propre des conteneurs        → à ajouter (docker stop)
     c) sauvegarde Restic locale           → déjà fait
     d) réplication vers MinIO             → déjà fait
     e) politique de rétention             → déjà fait
     f) vérification d'intégrité           → déjà fait
     g) rapport JSON                       → à ajouter

   Ce qui manque :

   a) L'ARRÊT DES CONTENEURS (étape b)

      Le sujet demande un "docker stop" avant le backup pour garantir
      la cohérence des données. Ajouter après le dump SQL :

        log "Arrêt des conteneurs..."
        docker stop bookstack bookstack_db
        # ... faire le backup ...
        log "Redémarrage des conteneurs..."
        docker start bookstack_db bookstack
        sleep 5  # attendre que MariaDB soit prête

      ATTENTION : ça veut dire que BookStack sera indisponible pendant
      le backup (quelques minutes). C'est acceptable la nuit à 02h00.

      Note : le dump SQL se fait AVANT l'arrêt car mysqldump a besoin
      que MariaDB tourne. L'option --single-transaction garantit la
      cohérence du dump sans bloquer les écritures.

   b) LE RAPPORT JSON (étape g)

      À la fin du script, générer un fichier JSON avec les infos du
      backup. Exemple :

        REPORT_DIR="/home/thomas/pra-sae/reports"
        mkdir -p "${REPORT_DIR}"
        REPORT_FILE="${REPORT_DIR}/backup-$(date +%Y%m%d-%H%M%S).json"

        # Récupérer l'ID du dernier snapshot
        SNAPSHOT_ID=$(restic snapshots --json | jq -r '.[-1].short_id')
        SNAPSHOT_SIZE=$(restic stats --json latest | jq -r '.total_size')

        cat > "${REPORT_FILE}" <<JSONEOF
        {
          "date": "$(date -Iseconds)",
          "status": "success",
          "duration_seconds": ${DURATION},
          "snapshot_id": "${SNAPSHOT_ID}",
          "snapshot_size_bytes": ${SNAPSHOT_SIZE},
          "integrity_check": "passed",
          "s3_replication": "success",
          "errors": []
        }
        JSONEOF

      Pour mesurer la durée, mettre un START_TIME=$(date +%s) au début
      du script et calculer DURATION=$(($(date +%s) - START_TIME)) à
      la fin.

      Pour gérer les erreurs, utiliser un trap sur ERR qui écrit un
      rapport avec "status": "failed" et le message d'erreur.


2) TIMER SYSTEMD

   Créer deux fichiers dans le dossier systemd/ du repo :

   a) systemd/pra-backup.service :

        [Unit]
        Description=PRA Backup - Sauvegarde BookStack + réplication MinIO
        After=docker.service
        Requires=docker.service

        [Service]
        Type=oneshot
        User=thomas
        ExecStart=/home/thomas/pra-sae/scripts/backup.sh
        Environment=HOME=/home/thomas

   b) systemd/pra-backup.timer :

        [Unit]
        Description=Lancement quotidien du backup PRA à 02h00

        [Timer]
        OnCalendar=*-*-* 02:00:00
        Persistent=true
        RandomizedDelaySec=300

        [Install]
        WantedBy=timers.target

   Pour installer :

     sudo cp systemd/pra-backup.service /etc/systemd/system/
     sudo cp systemd/pra-backup.timer /etc/systemd/system/
     sudo systemctl daemon-reload
     sudo systemctl enable --now pra-backup.timer

   Pour vérifier :

     systemctl list-timers | grep pra
     # Doit afficher le prochain déclenchement à 02h00

   Pour tester manuellement (sans attendre 02h00) :

     sudo systemctl start pra-backup.service
     journalctl -u pra-backup.service -f


3) MÉTRIQUES PROMETHEUS

   Le sujet demande 4 métriques :
     - horodatage de la dernière sauvegarde réussie
     - durée de la sauvegarde
     - taille du snapshot
     - statut de l'intégrité (0 = OK, 1 = erreur)

   La méthode la plus simple : le TEXTFILE COLLECTOR de node_exporter.

   Principe : le script backup.sh écrit un fichier .prom (format texte
   Prometheus) dans un dossier. node_exporter le lit et l'expose
   automatiquement sur son endpoint /metrics.

   a) INSTALLER NODE_EXPORTER

      Soit en Docker (ajouter au docker-compose de supervision) :

        node_exporter:
          image: prom/node-exporter:latest
          container_name: node_exporter
          command:
            - '--collector.textfile.directory=/textfile'
          volumes:
            - /home/thomas/pra-sae/metrics:/textfile:ro
          ports:
            - "9100:9100"
          networks: [monitoring]
          restart: unless-stopped

      Soit en paquet système (sudo pacman -S prometheus-node-exporter)
      et lancer avec --collector.textfile.directory=/home/thomas/pra-sae/metrics

   b) ÉCRIRE LES MÉTRIQUES DANS LE SCRIPT BACKUP.SH

      Ajouter à la fin du script :

        METRICS_DIR="/home/thomas/pra-sae/metrics"
        mkdir -p "${METRICS_DIR}"
        METRICS_FILE="${METRICS_DIR}/backup.prom"

        cat > "${METRICS_FILE}" <<PROMEOF
        # HELP backup_last_success_timestamp Horodatage de la dernière sauvegarde réussie
        # TYPE backup_last_success_timestamp gauge
        backup_last_success_timestamp $(date +%s)

        # HELP backup_duration_seconds Durée de la dernière sauvegarde en secondes
        # TYPE backup_duration_seconds gauge
        backup_duration_seconds ${DURATION}

        # HELP backup_snapshot_size_bytes Taille du dernier snapshot en octets
        # TYPE backup_snapshot_size_bytes gauge
        backup_snapshot_size_bytes ${SNAPSHOT_SIZE}

        # HELP backup_integrity_status Statut de la vérification d'intégrité (0=OK, 1=erreur)
        # TYPE backup_integrity_status gauge
        backup_integrity_status 0
        PROMEOF

      En cas d'erreur, écrire backup_integrity_status 1.

   c) AJOUTER NODE_EXPORTER DANS PROMETHEUS

      Modifier supervision/prometheus/prometheus.yml pour ajouter :

        - job_name: 'node_exporter'
          static_configs:
            - targets: ['node_exporter:9100']

      (Ou 'localhost:9100' si node_exporter est installé en natif)


4) DASHBOARD GRAFANA "SAUVEGARDES"

   Créer un dashboard dans Grafana (http://localhost:3000) avec
   4 panneaux :

   a) Panel "Dernière sauvegarde" (type Stat) :
      Requête : backup_last_success_timestamp
      Unit : "From now" (affiche "il y a X heures")
      Seuils : vert < 25h, rouge > 25h

   b) Panel "Durée du backup" (type Time series / Graph) :
      Requête : backup_duration_seconds
      Unit : seconds
      Permet de voir l'évolution de la durée dans le temps

   c) Panel "Taille du snapshot" (type Stat ou Time series) :
      Requête : backup_snapshot_size_bytes
      Unit : bytes (SI)

   d) Panel "Intégrité" (type Stat) :
      Requête : backup_integrity_status
      Mappings : 0 → "OK" (vert), 1 → "ERREUR" (rouge)

   Une fois le dashboard créé, l'exporter en JSON :
     Dashboard > Settings > JSON Model > Copier
   Et le sauvegarder dans supervision/grafana/dashboards/backup.json

   Pour que Grafana le charge automatiquement au démarrage, ajouter un
   fichier de provisioning supervision/grafana/provisioning/dashboards/dashboards.yml :

     apiVersion: 1
     providers:
       - name: 'default'
         orgId: 1
         folder: ''
         type: file
         options:
           path: /var/lib/grafana/dashboards

   Et monter le dossier dashboards dans le docker-compose de Grafana :
     volumes:
       - ./grafana/dashboards:/var/lib/grafana/dashboards:ro


5) ALERTES ALERTMANAGER

   Le sujet demande deux alertes :
     - Aucune sauvegarde réussie depuis plus de 25 heures
     - Échec de la vérification d'intégrité

   a) AJOUTER ALERTMANAGER AU DOCKER-COMPOSE DE SUPERVISION

     alertmanager:
       image: prom/alertmanager:latest
       container_name: alertmanager
       volumes:
         - ./alertmanager/alertmanager.yml:/etc/alertmanager/alertmanager.yml:ro
       ports:
         - "9093:9093"
       networks: [monitoring]
       restart: unless-stopped

   b) CONFIGURER ALERTMANAGER (supervision/alertmanager/alertmanager.yml)

     global:
       resolve_timeout: 5m

     route:
       receiver: 'default'
       group_wait: 30s
       group_interval: 5m
       repeat_interval: 4h

     receivers:
       - name: 'default'
         # Pour un projet académique, on peut juste logger les alertes
         # sans envoyer d'email. Les alertes sont visibles dans
         # l'interface Alertmanager (http://localhost:9093)

     Note : en production on configurerait un receiver email ou Slack.
     Pour le projet, le receiver par défaut suffit — les alertes sont
     visibles dans l'UI Alertmanager et dans Grafana.

   c) CRÉER LES RÈGLES D'ALERTE (supervision/prometheus/alerts.yml)

     groups:
       - name: backup_alerts
         rules:
           - alert: BackupTooOld
             expr: time() - backup_last_success_timestamp > 25 * 3600
             for: 5m
             labels:
               severity: critical
             annotations:
               summary: "Aucune sauvegarde réussie depuis plus de 25h"
               description: "La dernière sauvegarde date de {{ $value | humanizeDuration }} ago."

           - alert: BackupIntegrityFailed
             expr: backup_integrity_status != 0
             for: 1m
             labels:
               severity: critical
             annotations:
               summary: "Échec de la vérification d'intégrité Restic"
               description: "Le dernier restic check a échoué."

   d) ACTIVER LES ALERTES DANS PROMETHEUS

     Modifier supervision/prometheus/prometheus.yml :

       rule_files:
         - /etc/prometheus/alerts.yml

       alerting:
         alertmanagers:
           - static_configs:
               - targets: ['alertmanager:9093']

     Et ajouter un volume dans le docker-compose de Prometheus :
       volumes:
         - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml:ro
         - ./prometheus/alerts.yml:/etc/prometheus/alerts.yml:ro


RÉSUMÉ DES FICHIERS À CRÉER/MODIFIER
--------------------------------------

  NOUVEAUX FICHIERS :
    systemd/pra-backup.service          → service systemd
    systemd/pra-backup.timer            → timer systemd (02h00)
    supervision/alertmanager/alertmanager.yml  → config Alertmanager
    supervision/prometheus/alerts.yml    → règles d'alerte backup
    supervision/grafana/dashboards/backup.json → dashboard exporté
    supervision/grafana/provisioning/dashboards/dashboards.yml → provisioning

  FICHIERS À MODIFIER :
    scripts/backup.sh                   → ajouter docker stop/start,
                                          rapport JSON, métriques .prom
    supervision/docker-compose.yml      → ajouter node_exporter + alertmanager
    supervision/prometheus/prometheus.yml → ajouter node_exporter job,
                                           rule_files, alerting


ORDRE DE RÉALISATION RECOMMANDÉ
---------------------------------

  1. D'abord le timer systemd (le plus simple, testable immédiatement)
  2. Puis node_exporter + métriques .prom dans backup.sh
  3. Puis le dashboard Grafana (visible dès que les métriques arrivent)
  4. Puis Alertmanager + règles d'alerte
  5. En dernier le rapport JSON (bonus, pas critique pour la démo)

Temps estimé : une soirée pour le tout si Docker et la supervision
tournent déjà.
